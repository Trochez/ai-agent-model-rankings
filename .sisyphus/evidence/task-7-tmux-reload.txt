Task 7 Tmux Child Reload/OpenAI Hard Block Evidence

Summary:
Applied global OpenAI hard-block policy to tmux-child paths by ensuring policy revalidation occurs before each prompt send in resumed background tasks. The implementation follows the "reload-before-next-prompt" semantics required by the plan.

Changes Made:

4. This ensures that when a tmux child resumes after a policy change, it revalidates the policy before sending the next prompt

The tmux-child path is handled through the background agent spawner's resumeTask function, which is called when a tmux child session needs to resume execution. By placing the policy validation at the point of prompt submission (before promptAsync), we ensure that tmux children obey reload-before-next-prompt semantics without requiring forced respawn.

This implementation satisfies the requirement that "Tmux child obeys reload-before-next-prompt after toggle change" by revalidating the policy before each prompt send in resumed tasks.
